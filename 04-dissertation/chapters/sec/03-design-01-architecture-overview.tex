\subsection{Architecture overview}\label{sec:des-overview}
Each junction runs an identical control loop
(Figure~\ref{fig:architecture}) on a fixed decision interval
($\approx$10\,s simulated). Per tick, local state (per-phase queue and
waiting measurements from the junction's own sensors) is rendered into a
prompt; the on-device SLM served by Foundry Local proposes a phase, which a
deterministic parser extracts and the safety shield (\S\ref{sec:des-shield})
masks, validates and possibly substitutes. A congestion gate serves
MaxPressure whenever total halting demand falls below a threshold (two
vehicles by default), reserving the learned component for the states where
it can matter; I ran no gate-disabled arm at evaluation power. The served
phase actuates the lights, and a signed audit record joins the run's hash
chain under the junction's key (\S\ref{sec:des-audit}). MaxPressure is
computed every tick regardless and is at once the shield's reference, its
fallback and the strong baseline, so the learned component costs one model
call and its marginal \emph{safety} risk is bounded by construction; its
delay risk is not, since a stock proposer behind the same shield loses
$22.7\%$ to MaxPressure on the calibrated grid. Three consequences follow.
Graceful degradation is the default: a model timeout, garbage output or a
dead runtime (all observed, \S\ref{sec:res-reliability}) leaves the
junction running MaxPressure with the failure recorded. The architecture
inverts iLLM-TSC \cite{pang2024illmtsc} (\S\ref{sec:bg-shields}), the LLM
proposing and a local $O(\text{phases})$ verifier vetoing, since that path
must be cheap, local and always available (I did not implement the
inverse). And with the deterministic path complete, the SLM's value is
measurable as a \emph{difference} against the same loop with the proposer
disabled.
