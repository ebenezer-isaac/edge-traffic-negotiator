## 1. The one thesis (frozen; the headline)

> **Is an on-device Small Language Model (Microsoft Foundry Local) traffic-signal controller that can match or beat the MaxPressure baseline on a real London corridor (Euston Road A501), WHILE providing a cryptographically-provable, tamper-evident audit of what and how happened during an accident, even POSSIBLE, and at what model scale / configuration does it become possible?**

An EXPLORATORY FEASIBILITY + SCALE-THRESHOLD study. The single question above has TWO coupled halves that must both hold for the system to be worth deploying:

- **H1 PERFORMANCE (can it control at all, and at what scale).** Can an on-device SLM controller match or beat the MaxPressure baseline on delay and throughput on the real Euston corridor, and at what model size + coordination configuration? The model is an experimental VARIABLE (phi-4-mini, phi-4-mini-reasoning, qwen2.5-0.5b, qwen2.5-1.5b; on-device, no cloud). The deliverable is a FEASIBILITY MAP over models x configurations {myopic, +coordination, +prediction} plus a SCALE THRESHOLD (the smallest model / simplest config at which parity-or-better with MaxPressure appears, if any).
- **H2 TRUST (can what it did be proven afterwards).** Is every decision provably auditable, so an accident is mechanically reconstructable? A signed hash-chained AuditLog + Merkle commitment + quorum external anchor + named cross-auditor + a deterministic origin classification + an evidence-pack-not-verdict forensic channel together let an investigator reconstruct, from cryptographically-verified records alone, what happened, how, and which signing key drove each decision, during a scripted accident.

**Nature of the contribution:** the thesis MAPS feasibility. It is legitimate for H1 to return a scale-threshold or an honest negative (e.g. "no on-device model in the catalog beats MaxPressure on delay, but the largest reaches parity with coordination"), and for H2 to return a bounded guarantee with a measured blind spot. Distinction is earned by experimental RIGOR, a real corridor, real on-device models, and an HONEST characterisation, NOT by a novelty theorem. Nothing built is wasted: the accountability layer, the policy base, the adversarial suite, and the MaxPressure baseline together form the STANDARD the SLM controller is measured against.

**H2 supporting boundary result (NOT the headline):** the H2 audit is not omniscient, and the thesis states exactly where it is blind. The self-referential coupling (§4.5) is the measured blind spot: because the preemption attack controls the signal phase, which is also the variable that gates honest-witness coverage, a stealthy insider can open a coverage desert that conceals a bounded, conservation-consistent deviation class. This is a security insight that ENRICHES H2 (it quantifies the audit's boundary), stated as a conditional lemma with one severe pre-registered measurement on the real corridor (Experiment D, §8). It is a supporting result, not the headline.

**What this thesis does NOT claim:** it does not claim a novel security primitive (the accountability mechanism is Certificate-Transparency-style, credited to prior art, cited); it does not claim an unconditional guarantee (the free-deviation boundary is reported, not defended); it does not claim "corridors in general" (Experiment D is a case study of one real corridor, geometry n=1); and it does not claim the SLM legal-reasoning note beats a template (Job A measured a fair negative, §4.6).

**Position vs prior art.** H1 sits against MaxPressure (Varaiya 2013) and learned/LLM signal control incl Traffic-R1; the differentiator is the on-device + provable-audit constraint pair, not a new control law. H2's accountability layer IS Certificate Transparency / accountability, CONCEDED and cited: RFC 6962, CONIKS (Melara 2015), A2M (Chun 2007), TrInc (Levin 2009), PeerReview (Haeberlen 2007), Haber-Stornetta 1991, Schneier-Kelsey 1999, Kusters CCS 2010; CT auditing needs multiple logs + auditors + gossip (Chuat CNS 2015). The §4.5 blind-spot draws on FDI (Liu-Ning-Reiter 2011, Teixeira-Sandberg 2015, Mo-Sinopoli 2010), observability topology-dependence (Kosut-Jia-Thomas-Tong IEEE TSG 2011, Hendrickx et al IEEE TAC 2014, Cardenas-Amin-Sastry HotSec 2008), time-varying/periodic observability (Bittanti-Colaneri, *Periodic Systems*, 2009), the domain-closest signal-attack work (Chen et al I-SIG NDSS 2018; Ghena et al WOOT 2014, which do NOT couple attack-lever to observability-gate), collusion vs TSC (Qu-Tang-Ma arXiv 2111.02845), non-repudiation != truthfulness (Li-Nejad-Zhang arXiv 1906.02628), and SLM legal-citation hallucination (Dahl et al 2024).

## 3. H1 PERFORMANCE: the on-device SLM controller vs MaxPressure, and the model x config sweep

**The system-under-test.** An on-device SLM traffic-signal controller: at each event-gated decision interval on the Euston A501 stretch, the SLM chooses the next phase (`choose_phase`) from the current queue/detector state, running entirely on Foundry Local with no cloud call. The SLM controller is the object of the H1 question "is it even possible."

**The baseline.** MaxPressure (Varaiya 2013), the deterministic safety-floor controller. MaxPressure is provably stable and throughput-optimal under saturating demand but is MYOPIC: it optimises each junction from local pressure alone and does not coordinate across the arterial or anticipate arrivals. H1 asks whether an on-device SLM can MATCH OR BEAT MaxPressure on delay and throughput.

**The beat-it levers.** MaxPressure's myopia is where an SLM controller can plausibly gain on a real arterial:
- **+coordination (neighbour-note).** On the real Euston arterial, upstream/downstream neighbour state can inform phase choice where MaxPressure ignores it. On the synthetic unit-test grid, coordination measures as a STRUCTURAL ZERO (an inert term on that topology), but that zero is SUBSTRATE-SPECIFIC to the synthetic topology. The real arterial, with genuine platoon progression and offsets, is where coordination CAN reduce delay; it is therefore a config-sweep arm and an OPEN experiment, not a settled zero.
- **+prediction.** Anticipating arrivals from upstream detectors, a lever MaxPressure lacks.

**THE HEADLINE EXPERIMENT: the MODEL x CONFIG SWEEP.** Measure delay, throughput, and per-decision latency of the SLM controller vs MaxPressure across the full grid {model in {phi-4-mini, phi-4-mini-reasoning, qwen2.5-0.5b, qwen2.5-1.5b}} x {config in {myopic, +coordination, +prediction}}, on the real Euston corridor. Protocol pinned in §8; inferential claims gated on real time-resolved demand (§8, §9).

**THE OUTCOME: a FEASIBILITY MAP + a SCALE THRESHOLD.** The deliverable is a map over the grid: for each cell, does the SLM controller match/beat MaxPressure on delay and throughput, and at what latency? From the map, report the SCALE THRESHOLD: the smallest model and simplest config (if any) that reaches parity-or-better. An honest negative ("no on-device model beats MaxPressure on delay") and a conditional positive ("parity only at the largest model with coordination") are both valid, distinction-grade results. LIMITATIONS ARE ALLOWED (§0).

**HONEST STATUS: PILOT COMPLETE + APPROVED; NOW FULL-SCALE.** Both supervisors approved the pilot and the headline (2026-07-23); the project is in the full-scale implementation + experimentation phase (nothing deferred; throughput-alongside-delay, multi-seed, multi-map London, explanatory analysis, a multi-scenario crash→UK-law audit suite, and a trust-coefficient mechanism). The H1 SLM-vs-MaxPressure sweep was run as a labelled PILOT (n=1/cell, `results/experiment_sweep.md`) and is now being scaled up: on-device SLM control BEATS myopic MaxPressure on delay under saturating demand, with the scale threshold at the SMALLEST model (`qwen2.5-0.5b`) at the SIMPLEST config (myopic), −25% mean delay, audit live per cell, per-decision latency under the 10 s interval; `phi-4-mini-reasoning` is latency-gated (~8.5 s/decision) and `+coordination` is causally inert on this linear-spine substrate (reported as such). Because Euston demand is DfT-daily-AADF calibrated (temporal profile assumed), this is a DESCRIPTIVE pilot only: no significance/inferential claim is made, and the powered n≥30 runs are honestly gated (§8) until real time-resolved TfL counts land (`src/experiment_powered_gate.py`).

**Latency is part of H1.** Per-decision latency decides whether the SLM controller is viable on the ~10 s event-gated interval at all. Latency is profiled per job via the FLPerformance nearest-rank method (§8, D-lat), reported as {n, min, P50, P95, P99, max, mean}. The already-measured Job-A note latency (P50 37.8s / P99 40.8s, `results/experiment_jobA.md`) is why the SLM legal-reasoning note is POST-HOC and off the real-time control path (§4.6); the controller `choose_phase` latency against the decision interval is the H1 real-time-viability question and is measured in the sweep.

## 4. H2 TRUST: the provable, tamper-evident accident audit

The H2 half asks whether every decision is provably auditable so an accident is mechanically reconstructable. The answer is built from a signed accountability log, a deterministic safety gate, a deterministic origin classification, an evidence-pack-not-verdict forensic channel, and a scripted accident-reconstruction demo. Its measured BLIND SPOT (the coupling, §4.5) is reported honestly. The SLM legal-reasoning note (§4.6) is a NON-EVIDENTIAL support whose Job-A value is a measured negative.

### 4.1 The provable audit (mechanism, conceded to prior art)

Every message, every signed sighting, and every decision is appended to a signed, hash-chained `AuditLog` (sender-signature over the logical `message.t` + chain link). Batches produce a monotonic completeness commitment (Merkle root + `seq_high`) written to a QUORUM external anchor (>=2 witnesses: Rekor + a named single-node ledger RPC) and read by a NAMED cross-auditor for split-view detection. The mechanism is Certificate-Transparency-style accountability, CONCEDED to prior art and cited (§1, §6.7); the contribution is its ROLE in making an accident reconstructable on a real signalised corridor, not the primitive. The cross-auditor's honesty/independence is an UNVERIFIED assumption (on par with the identity root); a single auditor is weaker than the cited CT multi-auditor gossip, and this is stated, not hidden.

### 4.2 The safety standard (the deterministic real-time gate)

The deterministic gate is the safety floor and the standard the SLM controller is measured against: Ed25519 auth + registry membership + conservation/CUSUM + a corroboration gate (key-bound, >=2 keys) + a need-functional magnitude bound over MEASURED inputs (VOID where the source shares the keyless-spoof surface, §6.6) + a hard refusal of keyless sustained preemption with a junction-aggregate cumulative keyless-transient budget (§6.4) + an anti-starvation shield (max_skip=3, §6.8). Full mechanism detail in §6. An admissible EV preemption always clears and always emits its decision record; an uncorroborated signed preemption from a compromised insider is refused. This gate is what an accident reconstruction verifies against.

### 4.3 Origin classification + the evidence pack (evidence-pack, not verdict)

Post-incident, `assessment.py` (a full rewrite over the pinned schema, §6.3) verifies chain + per-record signature + quorum-completeness + cross-audit BEFORE attributing anything, refusing (`UNKNOWN` / `INCOMPLETE_DISCLOSURE`) on any failure. Origin is a DETERMINISTIC partition over two mechanical features (signing-key count, recomputed-corroboration presence) deciding three classes (§2, §3-origin). It is a ~100% VERIFICATION CHECK, explicitly NOT a measured contribution, and it NEVER reads the runtime `classification` field for origin. The output SPLITS into (i) a mechanically-verifiable EVIDENCE PACK carrying only reproducible facts through a CLOSED forensic channel (no verdict/confidence/accusation; header "Provenance record; not a determination of legal fault", §7) and (ii) a firewalled, non-evidential, counsel-gated internal note (§4.6). Where an origin is a signing party it names a KEY, never a person.

### 4.4 The accident-reconstruction demo (the H2 headline demonstration)

The concrete H2 demonstration: SCRIPT an accident on the corridor (a scripted phantom advance-claim AND a real-EV incident wired into `IntegratedSystem.run()` behind `enable_ev_incident=`, against a NAIVE victim `corroboration_required=False`), then show that from the verified audit ALONE an investigator can mechanically reconstruct WHAT happened (the decision sequence and executed phases), HOW (the driving signed inputs and which policies fired), and WHICH KEY drove the causal decision (the `ev_id` causal walk over `driving_input_seqs`). The demo passes only when the reconstruction is derived from cryptographically-verified, quorum-complete, cross-audited records, and a tamper (one substituted `sender_signature` that keeps `verify_chain()==True`) is caught by `identity.verify` (§6.3). This is the operational proof of "an accident is mechanically reconstructable," gated by D-accident (§12).

### 4.5 The measured blind spot of the audit (the self-referential coupling; SUPPORTING result)

The H2 audit is not omniscient, and H2 states exactly where it is blind. **The self-referential coupling:** the preemption attack controls the signal phase, which is ALSO the variable that gates honest-witness coverage, so executing the attack opens the very coverage desert that conceals it. This is the measured blind spot of the audit, a security insight that ENRICHES H2 (it quantifies the boundary); it is a supporting result, not the thesis headline.

Stated as a conditional LEMMA with explicit SUFFICIENT hypotheses (near-definitional; content in the empirically-measured coverage threshold, NOT a "theorem"): `[phase-coupled coverage of the footprint within its live phase window > threshold] AND [honest independent corroboration keys only] AND [cross-audited non-equivocating quorum] AND [no operator creation-time omission]` => every deviation is caught live or leaves a quorum + cross-audit-detectable trace. The self-referential twist: the attacker controls the phase that gates the coverage, so the attacker can open the coverage desert. The domain-specific increment (not owned by Kosut/Hendrickx/FDI/I-SIG/Ghena, and distinct from routine time-varying observability per Bittanti-Colaneri 2009) is the coupling instantiated + MEASURED on a real signalised corridor.

**The one severe pre-registered measurement** (Experiment D, §8): how the real Euston signal-phase-coupled sighting-coverage geometry shifts the deviation-escape surface AWAY from the well-mixed prediction, with a real null band that could refute it, on documented A501 detector placement, as a case study of one corridor (geometry n=1). The canonical free-deviation boundary (§0) is the finding: reported, not defended. The in-scope guarantee's near-vacuity (the substantive resisted content needs >=2 honest keys = out of scope) is stated honestly.

### 4.6 The SLM legal-reasoning note (H2 support; Job A measured NEGATIVE)

The on-device SLM also writes the internal, non-evidential, counsel-gated legal-reasoning note over the verified audit window. This is a second H2 SUPPORT, NOT the instrument of any boundary map (scored origins are decided by mechanical predicates, not the SLM). Its Job-A value is a MEASURED NEGATIVE, reported honestly.

## 14. The fine-tuned-SLM axis (scope expansion 2026-08-06; supervisor-directed)

**Decision record.** Directed by supervisor Akin Delibasi (meeting 2026-08-06), approved by the user. Feasibility research (four independent tracks, same date): `specs/001-edge-negotiator/finetune-feasibility.md`. This section is the sole governing spec for the expansion.

### 14.1 What it is and is not

The expansion asks: **does distilling frontier-model decision competence into an on-device SLM via LoRA/QLoRA close the measured per-decision gap (Claude 96% vs phi-4-mini 72% vs qwen3-0.6b 51% on the 80-state battery), and does any closed-loop effect follow?** It EXTENDS the frozen headline's configuration axis to {stock, fine-tuned}; it does NOT alter the thesis question (§0/§1), the substrate, the baselines (MaxPressure + fixed-time floor), the shield/audit architecture, or the serving requirement. Serving remains Foundry Local on the RTX 2060 at the ~4GB ceiling; ONLY training may run off-device (local RTX 2060 or rented UCL GPU). Prior art is credited, not claimed: the recipe is LLMLight/LightGPT-style imitation fine-tuning (teacher demonstrations, verifier filter, LoRA; KDD 2025, cited), with Claude as teacher, SUMO-London substrates, and a deterministic verifier replacing their RL critic. Honest expectation, pinned BEFORE any run: the literature's closed-loop fine-tuned-LLM gains over MaxPressure are ~1-2%, and our stock SLM already matches MaxPressure at n=30 - so the PRIMARY endpoint is per-decision competence; a null closed-loop result is a valid reported outcome.

### 14.2 Models

- **Primary: qwen3-0.6b** (largest headroom, trains on the 2060, cleanest tooling, mirrors LightGPT's 0.5B precedent).
- **Stretch (only if the primary completes early): phi-4-mini** (needs the 4090; patched-checkpoint + pad/eos-token cautions per the feasibility doc).

### 14.3 The pipeline (each step fail-loud)

1. **FT-0 pipeline proof (FIRST; go/no-go).** Olive-compile the STOCK qwen3-0.6b HF checkpoint to int4 ONNX, register it in the Foundry Local model cache (`inference_model.json` with Name + PromptTemplate from the tokenizer chat template), serve it, and run one existing sweep cell against it end-to-end. NO dataset or training work before FT-0 passes. Record the pinned Foundry Local version; a version upgrade invalidates FT-0 until re-validated. If FT-0 cannot pass, the documented fallback (ONNX Runtime GenAI, the same Microsoft runtime) may be used ONLY with the user's explicit approval and must be reported as a deviation from Foundry Local proper.
2. **Prompt canonicalisation.** The battery prompt builder is made byte-identical to the live `slm_agent.py` prompt (system + user format, including the trailing `/no_think` for qwen3-family serving IDs). The fine-tune trains ONLY on the live format. The served fine-tune's model ID keeps the `qwen3` substring so the existing `think_suffix` behaviour is unchanged.
3. **Dataset (distillation with rejection sampling).** Sample ~10k junction states via the CPU-only SamplingAgent path, stratified over topology x seed x demand level, deduplicated on unique halting vectors. Claude labels k candidates per state via in-session subagents (no API); a DETERMINISTIC verifier filters labels (legal-phase rule checks + the delay-aware greedy reference) - no LLM-as-judge. Target 2,000-5,000 accepted examples; train targets emit exactly the parseable form `{"phase": N}`. A stratified held-out set (300-500 states) is frozen BEFORE training, with a dataset battery (dedupe, stratification, leakage) as the build gate.
4. **Training.** Unsloth QLoRA (fallback: HF PEFT/TRL), r=16-32, lr ~2e-4, 1-3 epochs, early stopping on held-out loss; non-thinking targets only (empty think block), stated as scoped. Merge to bf16 (NEVER export from a 4-bit checkpoint), then Olive int4 compile.
5. **Offline eval AT INT4 AS SERVED (never the fp16 checkpoint):** held-out phase accuracy vs stock, 80-state battery accuracy vs stock, JSON-validity rate, and the temp-0 determinism probe. Gate: the fine-tune must beat the stock model on held-out battery accuracy at int4, else the result is reported as a negative and the closed-loop stage is skipped.
6. **Closed-loop eval:** existing harness unchanged (`experiment_frontier.py --models <served-id>` CATALOG fall-through), n>=30 seeds, Old Street + Euston peak-hour, myopic + sota, vs stock + MaxPressure + fixed-time, under the §8 stats protocol. Latency reported per D-lat.
